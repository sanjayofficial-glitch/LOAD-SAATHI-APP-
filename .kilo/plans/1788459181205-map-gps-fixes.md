# Map & GPS Tracking Fixes — Implementation Plan

## Problem Summary

Multiple map/GPS issues reported by both shippers and truckers:
1. **Map not showing in trip/shipment detail pages** ("view details" → no map)
2. **Share location / Enable button causes app to stop/freeze**
3. **Location not showing / map not loading**
4. **Truck shows as "standing" instead of "in transit" after starting trip**
5. **Trucker dashboard map broken**

## Root Causes Identified

### 1. Critical: `driver_locations` RLS policy too restrictive (PRIMARY CAUSE)
**File:** `supabase/migrations/20260902_fix_driver_locations_rls.sql`
**Policy:** `"Users can see own location or admin"`
```sql
CREATE POLICY "Users can see own location or admin"
  ON public.driver_locations
  FOR SELECT TO authenticated
  USING (auth.jwt()->>'sub' = driver_id OR public.is_admin());
```

**Impact:**
- Shippers can no longer read trucker locations → `ShipmentDetail.tsx` and `TripDetail.tsx` queries return empty → `LiveMap` renders with no truck data
- Truckers on dashboard can only see their own location, not all active trucks
- Supabase Realtime respects RLS → non-owners receive zero `postgres_changes` events for `driver_locations`
- This single policy change broke **all** cross-user map visibility

### 2. `start_trip` / `mark_trip_delivered` / `complete_trip` RPC functions not in local schema
**Files:** `TruckerTripDetail.tsx:129,182,235`
The app calls `supabase.rpc('start_trip', ...)` etc., but these functions are not defined in `final-schema.sql` or any local migration. If not deployed to Supabase, the calls fail silently (error toast shown, but status doesn't change).

### 3. `useLocationPermission` edge cases
**File:** `supabase/src/hooks/useLocationPermission.ts:29-32`
```tsx
if (typeof navigator.permissions === 'undefined' || !navigator.permissions.query) {
  setPermissionState('granted');
  return;
}
```
On platforms where `navigator.permissions` is missing (iOS Safari, Android WebView, non-HTTPS), the hook falsely reports `'granted'`. The `LocationPermissionBanner` never shows, and `AutoGpsTracker` attempts geolocation without explicit user consent, which can silently fail.

Additionally, `requestPermission` (lines 66-81) uses nested `getCurrentPosition` calls with `void`. On some platforms, the second attempt may not resolve the outer promise if the Geolocation API throws synchronously.

### 4. Map 0×0 pane fragility
**Files:** `LiveMap.tsx:18-25`, `RouteMap.tsx:33-40`, `LoadSaathiMap.tsx:26-33`
All map components rely on a single `setTimeout(() => map.invalidateSize(), 150)` to fix 0-height rendering. If the parent container's height isn't computed within 150ms (e.g., inside lazy-loaded routes, tabs, or animated transitions), the map stays blank. No retry or fallback exists.

### 5. `isTruckInTransit` logic treats posted trips as in-transit
**File:** `supabase/src/components/maps/TruckMarker.tsx:33-40`
```tsx
export function isTruckInTransit(truck: TruckLocation): boolean {
  if (truck.is_live === false) return false;
  return (
    truck.trip_status === 'in_transit' ||
    (truck.trip_id != null && truck.origin_city != null)
  );
}
```
A truck with `trip_status='active'` (posted but not started) shows as "in transit" because `trip_id` and `origin_city` are always populated by `AutoGpsTracker`. This makes the "in transit" icon misleading.

## Implementation Tasks

### Task 1: Fix `driver_locations` RLS policy (DB migration)
**Priority:** P0 — blocks all cross-user map visibility
**File:** New migration `supabase/migrations/20260903_fix_driver_locations_read_access.sql`

Replace the over-restrictive policy with one that allows:
- Driver to see own location
- Admin to see all locations
- **Shipper to see locations of truckers who accepted their shipments** (joined via `requests` or `shipment_requests`)
- **Any authenticated user to see locations of trucks with `in_transit` trips** (public tracking for active shipments)

```sql
-- Drop the broken policy
DROP POLICY IF EXISTS "Users can see own location or admin" ON public.driver_locations;

-- Driver sees own, admin sees all
CREATE POLICY "Driver or admin can manage own location"
  ON public.driver_locations
  FOR SELECT TO authenticated
  USING (
    auth.jwt()->>'sub' = driver_id
    OR public.is_admin()
  );

-- Public read for in-transit trips (shippers need this for live tracking)
CREATE POLICY "Anyone can see in-transit locations"
  ON public.driver_locations
  FOR SELECT TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM public.trips
      WHERE trips.id = driver_locations.trip_id
        AND trips.status = 'in_transit'
    )
  );
```

**Validation:** After deploying, verify:
1. Shipper can query `driver_locations` for their matched trucker
2. Trucker dashboard shows all active trucks (not just own)
3. Realtime events flow to non-owner subscribers

### Task 2: Verify / deploy missing RPC functions
**Priority:** P0 — prevents trip status transitions
**Files to check:** `supabase/FULL_REPAIR.sql` (definitions missing locally)

Ensure these functions exist in Supabase and are granted to `authenticated`:
- `public.start_trip(p_trip_id uuid)`
- `public.mark_trip_delivered(p_trip_id uuid)`
- `public.complete_trip(p_trip_id uuid)`

If missing, add migration with definitions that:
1. Verify the caller is the trip's trucker
2. Update `trips.status`
3. Update linked `shipments.status` to match
4. Return `{ success, error }` JSON

### Task 3: Fix `useLocationPermission` robustness
**Priority:** P1 — causes "stopping" on location enable
**File:** `supabase/src/hooks/useLocationPermission.ts`

Changes:
1. When `navigator.permissions` is unavailable, default to `'prompt'` instead of `'granted'` so the banner actually shows
2. Rewrite `requestPermission` to use a single `getCurrentPosition` call with proper timeout handling; avoid nested calls that may not resolve
3. Add explicit handling for `POSITION_UNAVAILABLE` (code 2) — don't silently retry, surface the error

```tsx
// Before: defaults to 'granted' when permissions API missing → banner never shows
if (typeof navigator.permissions === 'undefined' || !navigator.permissions.query) {
  setPermissionState('prompt');  // was 'granted'
  return;
}
```

### Task 4: Harden map rendering against 0×0 containers
**Priority:** P1 — map blank on some routes/pages
**Files:** `LiveMap.tsx`, `RouteMap.tsx`, `LoadSaathiMap.tsx`, all files in `components/maps/`

Changes:
1. Add `useRef` + `useEffect` with `ResizeObserver` on the map container to call `invalidateSize()` whenever dimensions change
2. Add a fallback `min-height` on all map wrapper divs (e.g., `min-h-[200px]`)
3. In `RouteMap`, if geocoding returns `null` for both cities, show a retry button instead of a dead-end error state

### Task 5: Fix `isTruckInTransit` to use actual trip status
**Priority:** P2 — misleading "in transit" badges
**File:** `supabase/src/components/maps/TruckMarker.tsx:33-40`

Change to rely primarily on `trip_status`:
```tsx
export function isTruckInTransit(truck: TruckLocation): boolean {
  if (truck.is_live === false) return false;
  return truck.trip_status === 'in_transit';
}
```

This requires `AutoGpsTracker` to correctly write `trip_status` from the refreshed trip context. Verify `refreshTripContext` in `AutoGpsTracker.tsx:60-86` queries `status` and writes it.

### Task 6: Add error boundaries and fallback UI for maps
**Priority:** P2 — prevents blank screens from crashing the whole page
**Files:** `components/ErrorBoundary.tsx`, all map components

1. Wrap each `MapContainer` in an error boundary that shows "Map failed to load" with a retry button
2. Add `onError` handlers to tile layers to fall back to a simpler tile provider if the primary one fails

### Task 7: Ensure `driver_locations` schema is complete
**Priority:** P2 — missing columns cause silent GPS write failures
**Files:** `supabase/migrations/20260805_add_trip_context_to_driver_locations.sql`, `supabase/apply-all-missing.sql`

Verify these columns exist on `driver_locations`:
- `trip_id`, `origin_city`, `destination_city`, `vehicle_type`, `available_capacity_tonnes`, `is_sharing`, `trip_status`, `last_seen_at`

If any are missing, add them via migration.

## Rollout Order

1. **Deploy DB migration** (Task 1) — fixes the most user-visible breakage
2. **Deploy RPC functions** (Task 2) — unblocks "Start Trip" flow
3. **Push frontend fixes** (Tasks 3-6) — can be deployed in any order after DB is fixed
4. **Verify schema** (Task 7) — run as a quick audit after deployment
